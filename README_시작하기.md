# STORY 퀴즈 제작 — 이관 패키지

STORY 원고를 넣으면 Lv1~Lv4 퀴즈 초안과 1차 검수 결과가 한 번에 나오게 하는 작업 폴더다.
**이 폴더 하나만 있으면 다른 컴퓨터에서 이어서 작업할 수 있다.** (2026-08-28 기준 상태 포함)

## 0. 준비물

| 필요한 것 | 확인 방법 |
|---|---|
| **Claude Code** | 터미널에서 `claude` |
| **Node.js** | 터미널에서 `node -v` — 미리보기·대시보드 생성기에만 쓴다 |

API 키·계정 설정·설치할 패키지는 따로 없다. 인터넷이 없어도 미리보기 HTML은 열린다
(글꼴만 온라인에서 받아오고, 실패하면 시스템 글꼴로 대체된다).

## 1. 시작하기

1. 이 폴더를 통째로 원하는 위치에 둔다. **폴더 이름과 경로에 한글·공백이 있어도 된다.**
2. 이 폴더에서 `claude` 를 실행한다.
3. 첫 지시로 아래를 그대로 붙여넣는다.

```
기록/진행상황.md 부터 읽고, 지금 상태와 다음에 할 일을 알려줘.
```

`CLAUDE.md`(규칙)와 `.claude/agents/`(서브에이전트 3종)는 Claude Code가 자동으로 읽는다.

## 2. 폴더가 무엇으로 이루어져 있나

```

PRD / SPEC / PLAN        요구사항·기능명세·실행계획 (서로 참조한다)
.claude/agents/          퀴즈생성자 · 대단원누적자 · 검토자

재료/                    입력. 절대 수정하지 않는다
  최종 원고_텍스트변환/    ← 에이전트가 실제로 읽는 원고 44건 (.md)
  최종 원고/              ← 원본 .docx 44건 (사람이 대조용. 에이전트는 못 읽는다)
  Story전체 목차_0730.csv  ← 분과·중단원·아티클 매칭 기준
  워크시트C…csv            ← 과제 정의 원본
  템플릿 예시…csv          ← 팀 구글시트 17열 형식
  iKAOS…v3.md             ← 최초 프롬프트 템플릿 원본

산출물/
  퀴즈제작현황_대시보드_v2.html    ← 전체 진행 현황 한 화면. 아티클마다 미리보기 링크가 붙는다
  퀴즈생성_프롬프트_템플릿_v5.md   ← 실행용 프롬프트 (유일). v4는 이력 보관용 구버전
  퀴즈_AB_2안_생성기준.md         ← 14문항(A/B 2안) 생성 기준
  도구/                          ← 미리보기·대시보드 생성기
  대단원별/*.csv (9개)            ← 최종 결과물. 128개 아티클 × 7행 스켈레톤
  퀴즈데이터/*.json (0개)         ← 생성한 퀴즈 (자리마다 A/B 2안). 2026-08-28 전량 재생성으로 비움
  퀴즈미리보기/*.html (0개)       ← 사람이 풀어보고 고르는 화면

기록/
  진행상황.md   ← 지금 상태와 다음 할 일. 세션을 시작하면 이것부터 읽는다
  HISTORY.md    ← 한 일의 이력 (시간순 누적)
```

## 3. 한 건을 처리하는 흐름

```
원고 1건  →  퀴즈생성자  →  JSON 저장  →  미리보기 생성  →  사람이 7개 선택  →  대단원누적자  →  CSV
                (14문항)                     (HTML)          ("확인했어")           (7행 채움)
```

1. **퀴즈생성자** 호출 — 원고 **절대경로**와 "이 원고 하나만 처리, 큐의 다음 건을 스스로 고르지 말 것"을
   반드시 적는다. 문항 규칙은 에이전트 정의와 템플릿에 이미 들어 있으니 옮겨 적지 않는다.
2. 결과를 받으면 **문항 본문이 잘리지 않았는지 먼저 세어 본다.** 빠졌으면 빠진 부분만 다시 요청한다.
3. `산출물/퀴즈데이터/<이름>.json` 으로 **즉시 저장**한다. 저장하지 않으면 세션이 끊길 때 사라진다.
4. 미리보기를 만든다 — 손으로 쓰지 않는다.
   ```
   node "산출물/도구/미리보기생성.js" "산출물/퀴즈데이터/<이름>.json"
   ```
5. `산출물/퀴즈미리보기/<이름>.html` 을 브라우저로 열어 14개 중 **최대 7개**를 고른다.
   마음에 들지 않는 자리는 「다시 만들 문항 고르기」에 담아 저장한다. 7개를 다 채우지 않아도
   「선택 결과 복사」가 눌린다 — 고른 것과 다시 만들 것이 한 번에 복사된다.
   잘 나온 문항에는 **★ 별표(모범 문제)** 도 찍는다(선택 체크박스와 별개). 2026-09-01에 별표 8건을
   분석해 「☆ 모범 문항 지향 원리」를 만들었으므로 **다음 라운드 품질에 직접 반영된다.**
6. 복사한 내용을 Claude Code에 붙여넣는다. 사람이 **"확인했어"** 라고 한 뒤에야 **대단원누적자**가
   `산출물/대단원별/*.csv` 의 해당 7행을 채운다.

## 4. 꼭 지킬 것 (자세한 내용은 `CLAUDE.md`)

- `재료/` 는 **읽기 전용**이다. 결과는 항상 `산출물/` 에 새 파일로 만든다.
- **원본에 없는 값을 지어내지 않는다.** 근거가 부족하면 `[확인 필요]` 로 표시한다.
- 사람이 **"확인했어"** 라고 하기 전에는 다음 단계로 넘어가지 않는다.
- CSV는 **UTF-8 (BOM 포함)** 으로 저장한다. BOM이 없으면 Excel에서 한글이 깨진다.
- **대단원별 CSV를 고치기 전에 그 파일이 Excel 등에 열려 있지 않은지 확인한다.** 잠긴 채로 시작하면
  7행 중 일부만 바뀐 상태로 실패해 문항과 정답이 어긋난다 (실제로 두 번 겪었다).
- 대단원별 CSV의 메타데이터 6열(분과·중단원·아티클·문항 번호·난이도·퀴즈 유형)은 **대조만 하고
  건드리지 않는다.** 문제~정답해설 11열만 채운다.

## 6. 이 패키지에 **넣지 않은** 것

원래 작업 폴더에는 있지만 재실행에 필요 없어 뺐다. 필요하면 원본 폴더에서 가져오면 된다.

- `산출물/웹앱/` — 실험용 로컬 서버
- `산출물/퀴즈미리보기/구버전/` — 옛 미리보기
- `퀴즈결과_원고_1_v2.md`, `시트업로드용_…csv` — 시범 검증용 레거시 산출물
- `퀴즈제작현황_대시보드.html`(구본) — 새 대시보드(`…_v2.html`)만 넣었다.
  언제든 `node "산출물/도구/build-dashboard.js"` 또는 `산출물/도구/대시보드_새로고침.bat` 더블클릭으로
  다시 만들 수 있다 (CSV·퀴즈데이터를 다시 읽어 수치와 링크를 갱신한다)
- `프롬프트_변경이력.md`, `재료/design/`, `재료/대시보드 디자인/` — 이력·디자인 자료
- **`재료/` 안에 있던 `CLAUDE.md`·`PRD`·`SPEC`·`PLAN` 사본** — 루트본보다 **낡았다.**
  기준 문서는 이 폴더 맨 위의 것을 읽어야 한다.

  이 서술은 어떤 문항의 근거로도 쓰지 않았다. 분과 기획자 확인 대상이다.
