# 슬라이드 제작 프롬프트 (재생성용)

이 파일 전체를 Claude Code 대화창에 붙여넣으면, 인터뷰를 다시 하지 않고 같은 발표자료를 만들 수 있다.
`gradiant-ai-project-deck` 스킬이 이 답변들을 1~6단계 답으로 받고, 7단계 제작안 승인만 한 번 물어본다.

```text

[4단계] 만든 이유와 현업 문제

주 3회 × 1건 40분씩 반복하고 있었다(월 약 8시간). 자동화 지점은 두 곳이다 —
① 원고가 바뀔 때마다 프롬프트 템플릿에 원고·메타데이터를 손으로 채워 넣는 일
② 형식·난이도·정답 표기 규칙 준수를 눈으로 점검하는 1차 검수
팀 목차가 확정되면서 아티클 129개 × 문항 7개 = 903문항이 순차로 들어올 예정이었다.
목표는 1건 15분, 1회차 검수 반려 50% 이하.
과학적 사실 오류·정답 타당성·최종 발행 승인은 분과 기획자 몫으로 그대로 유지한다.

[5단계] 제작 순서와 역할
1. 기준 문서를 하나 정해 자동화 구간 두 곳을 확정하고 작업 규칙을 문서로 고정
   (요구사항·기능명세·실행계획 3종)
2. 추측으로 만든 초안을 폐기하고, 팀이 쓰던 실제 프롬프트 템플릿을 기준 도구로 그대로 받아 씀
3. 시범 1건을 직접 풀어봄 — 자기검수는 전항목 통과였지만 형식 검사가 놓친 문장 문제가 드러남
4. 지적을 그 문항만 고치지 않고 문항 작성 원리와 한국어 문장 구조 검토 규칙으로 승격
   (자기검수 14항목)
5. 129건 규모로 확장 — 목차 자동 매칭, 대단원별 누적 CSV 9개(스켈레톤 903행),
   서브에이전트 3종, 검수 화면·현황 대시보드 생성기

AI 도구가 한 일
- 후보 14문항 생성과 자기검수 14항목 적용
- 팀 확정 목차와 대조한 메타데이터 자동 매칭
- 검수 화면·현황 대시보드 생성기 구현
- 검토자를 관점별로 병렬 호출해 산출물 자체 점검

내가 판단·수정한 일
- 자동화할 구간과 사람이 지킬 구간을 가른 결정
- 한국어 문장 구조 검토 규칙을 직접 작성해 전달
- 완성 문항을 직접 풀어보며 문장 문제를 지적
- AI가 임의로 붙인 글자 수 상한을 폐기하도록 지시
- 자리별 택일을 14개 중 최대 7개 자유 선택으로 변경

[6단계] 핵심 난관과 배운 점
반복해서 고친 것은 과학이 아니라 퀴즈 문장의 어순·단어·호흡·구조였다.
- 무엇이 안 됐나: 자기검수 전항목 통과였는데 직접 풀어보니 어순이 어색하고 한 문장의 호흡이 길고
  구조가 뒤엉킨 문항이 계속 나왔다.
- 무엇을 바꿨나: 걸린 문장을 직접 다듬어 기준을 뽑고, 한국어 문장 구조 검토 규칙을 직접 작성해
  프롬프트 템플릿과 에이전트 정의에 넣었다.
- 무엇이 달라졌나: 지적을 자기검수 항목으로 승격해 다음 원고부터 생성 단계에서 걸러지게 했다.
- 반대 방향의 사고: AI가 임의로 붙인 글자 수 상한이 정작 본인이 확정한 문장을 미통과로 판정했다.
  수치를 전부 지우고 정성적 기준으로 되돌렸다.
- 배운 점: AI가 통과시킨 것을 사람이 직접 해보는 단계는 줄일 수 없고, 사람이 지적한 것은 그 자리에서
  고치는 대신 규칙으로 남겨야 다음 건에서 되풀이되지 않는다.

[워크플로] 6단계 — 노드 주체 지정

과학적 사실 오류·정답 타당성·최종 발행 승인은 분과 기획자가 그대로 맡고 자동화 대상에서 제외했다.
```

## 재빌드만 다시 할 때

내용이 이미 `presentation/working/content.py`에 있으므로, 프롬프트를 붙여넣지 않고 값만 고쳐 다시 돌리면 된다.

```bash
python "presentation/working/build.py"
```

HTML 정본 → PDF → 페이지 PNG → PPTX가 한 번에 다시 만들어진다.
`presentation/working/render/slide-*.png`는 PDF·PPTX와 같은 픽셀이므로, 이 PNG를 한 장씩 열어보는 것이 곧 변환본 검수다.
